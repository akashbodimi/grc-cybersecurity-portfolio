# ISO/IEC 27001:2022 Gap Assessment — Scope

## 1. Organization

**Fictional company:** Northstar Cloud Services Pvt. Ltd.

Northstar is a fictional India-based B2B SaaS provider that hosts a customer workflow and analytics platform. It has approximately 85 employees, a remote/hybrid workforce, cloud infrastructure, customer support, engineering, sales and third-party SaaS dependencies.

## 2. Assessment objective

Evaluate a defined subset of the information-security management system against ISO/IEC 27001:2022 requirements and selected Annex A controls. The objective is to identify control gaps, associated risks, evidence needs and a prioritized remediation roadmap.

## 3. Assessment type

**Simulated internal gap assessment / portfolio project.**

This is not a certification audit, certification decision, legal opinion or assessment of a real organization.

## 4. In-scope processes

- Information-security governance
- Asset and information inventory
- Identity and access management
- Cloud-service governance
- Vulnerability management
- Security logging and monitoring
- Incident management preparation
- Business continuity / ICT readiness
- Security awareness
- Cryptographic protection
- Supplier/security evidence management

## 5. In-scope technology assumptions

- Cloud-hosted production SaaS environment
- Corporate Microsoft 365 tenant
- Central identity provider
- Endpoint management
- Source-code repository and CI/CD platform
- Central logging/SIEM capability
- Ticketing platform
- Third-party SaaS applications

## 6. Information types

| Information | Classification assumption | Examples |
|---|---|---|
| Customer data | Confidential | Customer records and uploaded business data |
| Authentication information | Restricted | Passwords, tokens, recovery information |
| Source code | Confidential | Application source and infrastructure code |
| Security logs | Confidential | Authentication, endpoint and cloud logs |
| Internal policies | Internal | Security and operational procedures |
| Public information | Public | Marketing and public documentation |

## 7. Assessment period

**Simulated assessment period:** Q3 2026.

## 8. Assessment assumptions

Where evidence is unavailable, the assessment records the control as **Not Evidenced** rather than assuming the control exists. The simulated evidence set is deliberately limited so that gaps can be demonstrated.

## 9. Out of scope

- Physical data-center controls operated solely by cloud providers
- Formal certification audit activities
- Financial controls outside information security
- Legal interpretation of privacy legislation
- Penetration testing itself

## 10. Assessment limitation

The project uses fictional facts and synthetic evidence. Results demonstrate the assessment methodology and documentation approach, not the compliance status of a real company.
